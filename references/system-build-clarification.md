# 系统建设意图澄清指南（3.0 MVP）

## 目标

在企业场景地图报告输出完成后，用尽量少的轮次补齐系统建设所需的关键信息，为后续多维表清单规划提供足够上下文。

MVP 要求：

- 最多进行 3-4 轮澄清
- 信息足够时提前停止
- 每轮只问最缺的一类信息
- 不要把所有问题一次性抛给用户

## 优先澄清维度

按优先级从高到低：

1. 系统目标
2. 主要使用角色
3. 核心业务流程
4. 当前痛点与约束
5. 是否需要流程图

## 提前停止条件

满足以下大部分条件时即可停止澄清，进入表清单规划：

- 已明确系统要解决的核心目标
- 已明确 1-3 类主要使用角色
- 已掌握关键业务流程主链路
- 已掌握当前主要痛点或效率瓶颈
- 已知是否需要生成流程图

如果报告阶段已经覆盖了某些维度，不要重复询问。

## 轮次控制规则

### 第 1 轮

优先确认系统目标和使用角色。

示例：

- “如果继续做系统构建规划，这套系统最核心想解决的是什么问题？”
- “这套系统未来主要是谁在用？是老板看总览，还是一线团队高频操作？”

### 第 2 轮

优先确认关键流程。

示例：

- “这套系统最核心的业务流程，通常会经过哪几个步骤？”
- “如果按从开始到结束来讲，业务主链路大概是怎样的？”

### 第 3 轮

优先确认痛点、卡点、约束。

示例：

- “当前最卡的地方是什么？是信息分散、协作混乱、审批慢，还是数据统计困难？”
- “有没有必须考虑的限制，比如多人协作、跨部门审批、数据合规，或者移动端使用？”

### 第 4 轮

只在仍有关键缺口时使用，通常用于确认流程图或补充遗漏信息。

示例：

- “你希望这次一起生成流程图辅助理解吗，还是先只搭好多维表结构？”
- “目前还有一个关键信息我没补齐：这套系统里最重要的结果产出是什么？”

## 提问原则

- 一次只问一类问题
- 优先复用报告阶段已获得的企业上下文
- 问题要贴近业务，不要像填表
- 只补对表清单规划真正必要的信息

## 不要这样做

- 不要要求用户一次性填写完整 PRD
- 不要在澄清阶段生成字段级设计
- 不要直接让用户输出最终接口 JSON
- 不要因为设定了 3-4 轮，就机械追问满轮次

## 输出要求

澄清结束后，智能体应在内部形成一份精炼的系统建设摘要，至少覆盖：

- 系统目标
- 主要角色
- 关键流程
- 核心痛点
- 是否需要流程图

这份摘要将作为多维表清单规划的输入上下文。
